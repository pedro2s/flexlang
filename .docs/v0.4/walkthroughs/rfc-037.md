# Walkthrough: Módulo de Validação Declarativa de Dados (`std/validator`) — RFC-037

## O que foi construído

1. **Módulo Nativo `std/validator` (`src/modules/validator.ts`)**:
   - **Validações Primitivas Prontas**:
     - `validator.cpf(str)`: Algoritmo de validação de CPF por módulo 11 com 2 dígitos verificadores, rejeitando sequências com dígitos repetidos.
     - `validator.cnpj(str)`: Algoritmo de validação de CNPJ com 2 dígitos verificadores e matriz de pesos canônica.
     - `validator.email(str)`: Expressão regular padrão para validação de endereços de e-mail.
     - `validator.uuid(str)`: Expressão regular para validação de identificadores únicos UUID (v1-v5).
   - **Validador Estruturado com Builder Pattern**:
     - Instanciado via `validator.new()`.
     - Encadeamento de regras por campo: `.field(name, value).required().min_len(min).max_len(max).email().cpf().cnpj().uuid().regex(pattern)`.
     - Adição manual de erros de negócio via `v.add_error(field, message)`.
     - Consolidação do resultado com `v.result()`, retornando `Result<Void, [ValidationError]>`.

2. **Paridade Arquitetural (Node.js e Go)**:
   - **Runtime TypeScript**: Classes `FlexValidator` e `FlexFieldValidator` com mapeamento de struct `ValidationError { field, message }`.
   - **Transpilador Go**: Preâmbulo embutido com structs `ValidationError`, `Validator`, `FieldValidator` e funções estáticas de validação e encadeamento em Go.
   - **Aprimoramento do Transpiler**: Suporte correto a descarte de wildcard `_` em pattern matchings (`_ = bound.Field0`), impedindo erros de compilação em Go.

## O que foi testado

- **Tipagem Estrita**: `npx tsc --noEmit` executado com 0 erros.
- **Integração Node.js**: `tests/validator_integration.ts` validou CPFs, CNPJs, E-mails, UUIDs válidos e inválidos, DTOs de sucesso e agregação de múltiplos erros de validação.
- **Parity Gate**: `tests/36_validator.flex` compilado e executado nos dois modos com saída idêntica validada em `npm run test:parity`.
- **Regressão**: Suíte completa de 50 testes golden, HTTP, Postgres, Redis e FlexBank API 100% verdes.
