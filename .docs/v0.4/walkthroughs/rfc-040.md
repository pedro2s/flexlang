# Walkthrough — RFC-040: Mensageria de Eventos Financeiros (`mq/events`, `mq/kafka`)

## Resumo da Implementação

A **RFC-040** introduziu o módulo nativo de mensageria orientada a eventos (`mq/kafka` e alias `mq/events`) na FlexLang, viabilizando arquiteturas event-driven financeiras com garantia de paridade estrita (ADR-001) entre o modo interpretado (Node.js/TypeScript) e compilado (Golang/GoCodegen).

---

## Principais Recursos Adicionados

### 1. Configuração e Mensagens (`KafkaConfig`, `EventMessage`)
- **`KafkaConfig`**:
  - `brokers: Array<String>`: Lista de endereços de brokers Kafka.
  - `client_id: String`: Identificador da aplicação produtora/consumidora.
  - `group_id: String`: Identificador do Consumer Group.
  - `acks: String`: Nível de confirmação de escrita (`"all"`, `"1"`, `"0"`).
  - `timeout_ms: Int`: Timeout de conexão em milissegundos.
- **`EventMessage`**:
  - `key: String`: Chave de particionamento (hashing determinístico).
  - `value: String`: Conteúdo/payload do evento (JSON serializado).
  - `headers: HashMap<String, String>`: Cabeçalhos arbitrários (incluindo `traceparent` e `tracestate` do Distributed Tracing W3C).
  - `topic: String`, `partition: Int`, `offset: Int`: Metadados atribuídos na entrega e consumo.

### 2. Produtor de Eventos (`Producer`)
- `Producer.new(config: KafkaConfig) -> Result<Producer, String>`: Valida brokers e inicializa o produtor.
- `producer.publish(topic: String, message: EventMessage) -> Result<Void, String>`: Publicação individual determinística com balanceamento por partição via hashing.
- `producer.publish_batch(topic: String, messages: Array<EventMessage>) -> Result<Void, String>`: Publicação em lote atômica.
- `producer.close() -> Result<Void, String>`: Encerramento com liberação de recursos.

### 3. Consumidor de Eventos (`Consumer`)
- `Consumer.new(config: KafkaConfig) -> Result<Consumer, String>`: Valida `group_id` e brokers.
- `consumer.subscribe(topics: Array<String>) -> Result<Void, String>`: Subscrição de múltiplos tópicos.
- `consumer.listen(handler: |msg| -> Result) -> Result<Void, String>`: Processamento com callback com commit automático de offset após confirmação de sucesso do handler.
- `consumer.poll(timeout_ms?: Int) -> Result<Array<EventMessage>, String>`: Leitura sob demanda (batch polling) com avanço de offset.
- `consumer.close() -> Result<Void, String>`: Encerramento seguro.

### 4. Inferência de Tipos de Lambdas no TypeChecker
- Inferência inteligente no `src/checker.ts` para inferir o parâmetro `msg` como `EventMessage` dentro de `consumer.listen(|msg| { ... })`, eliminando a necessidade de anotações manuais redundantes no código do usuário.
