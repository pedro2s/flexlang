# Walkthrough: Driver Nativo de Cache e Locks Distribuídos (RFC-036)

## O que foi construído

1. **Injeção do ecossistema Redis**
Foi mapeada integralmente a fundação do módulo para caches rápidos de bancos em memória, criando a classe tipada global `Redis` (`src/modules/redis.ts`) exposta ao Transpilador e ao TypeChecker de forma idêntica e unificada, assim como o `postgresModule`.

2. **Paridade Arquitetural (*Parity Gate*)**
- *NodeJS*: A execução instantânea interpretada consome a lib terceira `ioredis`. 
- *Golang*: O transpilador constrói preâmbulos no codegen do arquivo chamando o módulo de referência em ecossistemas alta-concorrência `github.com/redis/go-redis/v9`. Para garantir que esse código exógeno de terceiros pudesse compilar na hora, injetamos suporte dinâmico a `go mod init` e `go mod tidy` durante os testes do `tests/parity_runner.ts` de todo o código gerado em `/tmp`.

3. **Mutex Global via Lua Script (*Locks Distribuídos*)**
Para segurarmos as duplicações de transações bancárias (Double-Spending), foi implementada uma trava mutex nativa sem loops de CPU com TTL de precisão em milissegundos via: `Redis.acquire_lock(key, duration)`. O código em TypeScript e em Go executa scripts primitivos de `.Eval` em linguagem `Lua` garantindo atômica e absoluta segurança contra condições de corrida entre pods e instâncias.

## O que foi testado

Todos os escopos descritos na RFC-036 foram avaliados:
- Conexão e tratamento nativo de `Result` e falhas.
- `set_ex`, `get`, `del`
- Comandos incrementais atômicos `incr`.
- Aquisições assíncronas concorrentes de `RedisLock` rejeitando acesso em repetição de token.
